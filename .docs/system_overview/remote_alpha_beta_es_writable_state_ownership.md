# Remote Alpha ES Writable-State Ownership — Retired Existing-Host Edge

## Decision

`Temporary compatibility edge`: Remote Alpha v1 writable-state readiness,
staging, ownership preparation, ES service-user migration, rollback generation,
and old-root planning are retired existing-host routes. The six internal
implementations are fixed exit-2 tombstones and the six public wrappers remain
unchanged delegators. The routes inspect no host or artifact, contact no
service, create no temporary or evidence file, and perform no mutation.

No read-only current-readiness mode, apply simulation, structured unsupported
artifact, or v2 replacement exists.

## Historical artifacts

Existing v1 fixtures and archived operator artifacts are historical evidence
only. They cannot authorize a fresh deployment, existing-host migration,
scheduler drain, submitter fence, ownership change, reclamation, archive, or
deletion. No live operator route parses or projects the retired readiness,
staging, or ES service-user schemas. No v2 replacement exists for this retired
family; the unrelated current EGS hardening v2 schema remains current.

## Current writable-state behavior

ES still qualifies configured staging and result roots, requires the bounded
owner model used by submit/result operations, exclusively creates each run
root, refuses every pre-existing object type, holds parent/root descriptors,
materializes no-follow and descriptor-relative, and revalidates the expected
tree immediately before the one Nomad registration.

Once run-root creation succeeds, the visible root is retained on every return.
There is no root marker, reopening, adoption, cleanup eligibility, quarantine
rename, scan, or recursive run-root deletion. Result publication is independent
and never authorizes staging mutation. Only an exact operation-local temporary
created by the current operation may receive bounded descriptor-relative
cleanup; that creates no later residue-cleanup authority.

## Later seams and costs

Governed staging reclamation is an ES-owned `Reopened redesign seam`.
Retention increases disk use, capacity pressure, sensitive-material residence,
and operator burden. A future design must address those costs explicitly.

Fresh-host provisioning is required for future infrastructure recovery, but a
complete supported fresh-host ES provisioner is not currently implemented.
Reuse of an old or nonempty host remains blocked without a separately governed
existing-host migration contract. No scheduler-drain or submitter-fence
contract exists.
